# Rust architecture guidelines authored in ai-rulez (governance)

## Context and Problem Statement

The plane model (ADR-0013) and its consequences — trait-first seams, module/visibility discipline,
determinism-first performance patterns — are guidelines every future change, human or AI-assisted,
needs to follow. `CLAUDE.md` (and any equivalent `AGENTS.md`) is the mechanism every agent working in
this repo actually reads, but it is currently maintained as a single hand-edited file. As the
guideline set grows (trait-first rules, module-size caps, BTreeMap-vs-HashMap determinism rules,
`memchr`/regex/streaming performance patterns), where should this content live so it stays a single
source of truth and reaches every consuming agent file without manual duplication or drift?

## Decision Drivers

- Guidelines must reach every agent-facing file (`CLAUDE.md`, and any future `AGENTS.md` or
  tool-specific equivalent) without being hand-copied into each one and drifting apart.
- The guideline set is naturally structured (trait-first seams; module discipline; performance
  patterns) and will keep growing as new planes/crates are added — it needs a source format that
  supports organized, incremental editing, not one large prose file.
- This is itself an architecture decision (where governance content lives, how it propagates) and
  deserves the same durability as the technical ADRs it encodes, distinct from their content.
- The mechanism must be cheap to keep correct: a generated file that silently goes stale is worse than
  no generated file.

## Considered Options

- Author guidelines as `.ai-rulez/rules/` source files, render `CLAUDE.md`/`AGENTS.md` via
  `ai-rulez generate`; generated files are never hand-edited.
- Keep hand-editing `CLAUDE.md` directly as the single source of truth; add `AGENTS.md` later as a
  manually-synced copy.
- Move guidelines into `docs/rust-architecture.md` prose and rely on agents reading docs on demand
  instead of a dedicated rules mechanism.

## Decision Outcome

Chosen option: "Author guidelines as `.ai-rulez/rules/` source, render via `ai-rulez generate`",
because it gives the guideline set exactly one source of truth with an explicit, re-runnable
propagation step to every consuming file, instead of hand-synced copies that inevitably drift.

Guidelines are organized into `.ai-rulez/rules/` source files (plus a plane map and crate graph under
`.ai-rulez/context/`), grouped by concern:

1. **Trait-first seams** — every plane boundary is a trait (declared in `monomyth-contracts`); depend
   on `dyn Trait`/`impl Trait`, never a concrete impl crate, across a boundary; impls are injected as
   `Arc<dyn …>` and selected by configuration; trait-ify only plane boundaries, never intra-crate code.
2. **Module and visibility discipline** — `pub(crate)` by default (minimal public surface); every
   genuinely `pub` item carries rustdoc with a `?`-based example; the module-size cap (~1000 lines
   triggers a split by concern, per the `module-size-cap` convention); newtypes at public boundaries.
3. **Performance patterns, determinism-first** — never swap `BTreeMap`/`BTreeSet` for `HashMap`/
   `HashSet` in or feeding serialized output, since iteration order is part of the deterministic
   contract; `ahash`/`foldhash` only for internal, non-serialized, order-irrelevant hot maps with a
   justifying comment; `memchr` for byte/substring scanning over large corpus text; compile regexes
   once (`LazyLock`); bounded streaming for network bodies with pre-allocation when size is known.

`ai_rulez generate` renders these sources into `CLAUDE.md` and any future `AGENTS.md`. **The generated
files are never hand-edited** — a change to guidance content always starts in `.ai-rulez/rules/`,
never in the rendered output. This mirrors how `artifacts/frameworks/*.json` is generated data that
`monomyth-core::story` reads but nothing hand-edits in place.

### Consequences

- Good, because there is exactly one place to add or change a guideline, and every consuming file
  (`CLAUDE.md` today, `AGENTS.md` or others later) regenerates from it — no manual copy-paste sync.
- Good, because grouping rules by concern (trait-first / module discipline / performance) keeps the
  source scannable as it grows, instead of one ever-longer prose file.
- Good, because "generated, never hand-edited" is a checkable property (a diff between a fresh
  `generate` run and the committed file should be empty), catching drift in review.
- Bad, because it adds a build/generation step to the guideline-authoring workflow — a contributor
  must remember to run `ai-rulez generate` after editing `.ai-rulez/rules/`; mitigated by a review
  rule that generated files carry a "do not edit, generated by ai-rulez" banner making direct edits
  obviously wrong on sight.

### Confirmation

`CLAUDE.md`/`AGENTS.md` regenerate byte-identical from `.ai-rulez/rules/` via `ai-rulez generate` with
no manual diff required after. Code review enforces that any PR touching guideline content edits
`.ai-rulez/rules/`, not the generated files directly, and that generated files carry the ai-rulez
"do not edit" banner at the top.

## Pros and Cons of the Options

### `.ai-rulez/rules/` source + `ai-rulez generate`

- Good, because it separates authoring (structured source) from distribution (generated files per
  consuming tool), which is exactly the shape needed once more than one agent-facing file exists.
- Good, because it makes staleness detectable (regenerate and diff) instead of relying on a human
  remembering to update every copy.
- Neutral, because it introduces a small amount of tooling dependency (`ai-rulez` itself) that this
  ADR now takes on as project infrastructure.

### Hand-edit `CLAUDE.md` directly, sync `AGENTS.md` manually later

- Bad, because it guarantees drift the moment a second consuming file exists — there is no mechanism
  forcing the two to agree, only discipline, which does not scale as the guideline set grows.

### Guidelines as `docs/rust-architecture.md` prose only

- Bad, because prose docs are read on demand, not force-fed into every agent's working context the
  way `CLAUDE.md` is; guidelines that matter for every change need to be in the file agents actually
  load, not one more doc among many.

## More Information

Relates to ADR-0006 (Rust over Python) whose conventions this formalizes, and ADR-0013 (trait-first
planes architecture), whose seam rule is guideline group 1 here. `docs/rust-architecture.md` is
authored as a human-readable mirror of the same `.ai-rulez/rules/` source, stating "source of truth:
`.ai-rulez/rules/`" so readers are never tempted to edit the mirror instead.
